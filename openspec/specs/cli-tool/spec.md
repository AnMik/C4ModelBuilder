# cli-tool Specification

## Purpose

Задаёт контракт запуска консольного приложения: какие параметры принимаются, что наблюдает
вызывающая сторона в виде кодов возврата, файлов и сообщений, и как инструмент поставляется
в контейнерном образе.

## Requirements

### Requirement: Параметры командной строки

Приложение SHALL принимать параметры `--solution` (`-s`, путь к файлу решения, обязательный),
`--output` (`-o`, каталог вывода, обязательный), `--max-depth` (`-d`, по умолчанию `15`),
`--output-type` (`-t`, по умолчанию `puml`), `--project` (`-p`), `--exclude` (`-e`) и
`--log-level` (`-l`, по умолчанию `Warning`).

#### Scenario: Отсутствующий или неверный файл решения

- **WHEN** запуск выполняется без `--solution`, или файл не существует, или расширение не `.sln`
- **THEN** выводится сообщение об ошибке и код возврата равен `1`

#### Scenario: Значения по умолчанию

- **WHEN** `--max-depth`, `--output-type` и `--log-level` не указаны
- **THEN** используются значения `15`, `puml` и `Warning` соответственно

#### Scenario: Ограничение анализа одним проектом

- **WHEN** указан `--project`
- **THEN** анализируется только проект с указанным именем (сравнение без учёта регистра),
  а `--exclude` не применяется

#### Scenario: Исключение проектов маской

- **WHEN** указан `--exclude`, а `--project` не указан
- **THEN** из анализа исключаются проекты, имя которых совпадает с маской (`*` и `?` —
  подстановочные знаки), сравнение без учёта регистра

### Requirement: Версия и справка

Приложение SHALL по флагу `--version` выводить номер версии инструмента, а по флагам `--help` и `-h`
— справку с перечнем параметров. Оба действия SHALL завершаться с кодом возврата `0`, SHALL NOT
требовать обязательных параметров `--solution` и `--output` и SHALL NOT выполнять анализ решения.
Формулировка справки контрактом не является: гарантируется только наличие в выводе перечня
параметров.

#### Scenario: Запрос версии

- **WHEN** запуск выполняется с единственным параметром `--version`
- **THEN** в поток вывода (не ошибок) печатается номер версии инструмента, анализ решения не
  выполняется, код возврата равен `0`

#### Scenario: Запрос справки

- **WHEN** запуск выполняется с параметром `--help` или `-h`
- **THEN** печатается справка с перечнем параметров, анализ решения не выполняется, код возврата
  равен `0`

#### Scenario: Версия вместе с другими параметрами

- **WHEN** `--version` указан вместе с любыми другими параметрами
- **THEN** печатается сообщение об ошибке, анализ решения не выполняется, код возврата равен `1`

#### Scenario: Версия соответствует версии сборки

- **WHEN** запуск выполняется с параметром `--version` на сборке с версией `X.Y.Z`
- **THEN** в выводе присутствует `X.Y.Z`

### Requirement: Коды возврата

Приложение SHALL возвращать `0` при успешном завершении, `1` при ошибке разбора аргументов или
при необработанном исключении, и `130` при прерывании по запросу пользователя.

#### Scenario: Успешное завершение

- **WHEN** анализ и запись файлов завершились без ошибок
- **THEN** код возврата равен `0`

#### Scenario: Прерывание пользователем

- **WHEN** пользователь прерывает выполнение
- **THEN** код возврата равен `130`

#### Scenario: Необработанная ошибка

- **WHEN** во время выполнения возникает исключение
- **THEN** оно записывается в лог, и код возврата равен `1`

### Requirement: Формирование выходных файлов

Для каждого корневого класса приложение SHALL записывать отдельный файл в каталог `--output`,
с именем `{имя класса}.{расширение}` без пространства имён в имени. Каталог вывода SHALL уже
существовать: приложение его не создаёт и SHALL завершаться ошибкой при его отсутствии.

#### Scenario: Один файл на корневой класс

- **WHEN** анализ даёт несколько корневых классов
- **THEN** в каталоге вывода появляется отдельный файл для каждого из них

#### Scenario: Одноимённые корневые классы

- **WHEN** два корневых класса из разных пространств имён имеют одинаковый идентификатор
- **THEN** они записываются в один и тот же файл, содержимое последнего затирает предыдущее

#### Scenario: Отсутствующий каталог вывода

- **WHEN** каталог, указанный в `--output`, не существует
- **THEN** запуск завершается ошибкой с кодом возврата `1`, каталог не создаётся

#### Scenario: Пустой результат отбора

- **WHEN** отбор проектов не дал ни одного корневого класса
- **THEN** файлы не создаются, а код возврата равен `0`

### Requirement: Тип выходного файла

Приложение SHALL поддерживать значение `puml` параметра `--output-type` и SHALL принимать
значение `mermaid`, не поддерживая его: разбор аргументов проходит успешно, а выполнение
завершается исключением о нереализованной возможности.

#### Scenario: Запрос неподдерживаемого типа

- **WHEN** указано значение `--output-type mermaid`
- **THEN** запуск завершается ошибкой с кодом возврата `1`

### Requirement: Вывод сообщений

Минимальный уровень вывода сообщений SHALL определяться параметром `--log-level`. Сообщения
текущей версии формулируются на русском языке. При уровне по умолчанию собственные сообщения
приложения SHALL NOT выводиться.

#### Scenario: Успешный запуск при уровне по умолчанию

- **WHEN** запуск завершился успешно, а `--log-level` не указан
- **THEN** собственные сообщения приложения в консоль не выводятся

#### Scenario: Информационный уровень

- **WHEN** указан `--log-level Information`
- **THEN** в консоль выводится путь каждого созданного файла

#### Scenario: Отладочный уровень

- **WHEN** указан `--log-level Debug`
- **THEN** в консоль выводится дерево вызовов для каждого корневого класса

### Requirement: Поставка в контейнерном образе

Инструмент SHALL поставляться в контейнерном образе, содержащем .NET SDK, а не только среду
выполнения, поскольку анализ решения загружает MSBuild-проекты. В образе SHALL быть доступна
команда `c4builder`, а процесс SHALL выполняться от непривилегированного пользователя. Образ SHALL
нести номер версии инструмента: публикуются теги `X.Y.Z` (версия сборки) и `latest`, а метаданные
образа SHALL сообщать ту же версию.

#### Scenario: Запуск через команду образа

- **WHEN** образ запущен и вызвана команда `c4builder`
- **THEN** она принимает те же параметры, что и точка входа, и выполняет анализ

#### Scenario: Непривилегированный пользователь

- **WHEN** запущен контейнер
- **THEN** процесс выполняется от пользователя, отличного от `root`

#### Scenario: Версионный тег образа

- **WHEN** опубликован образ для версии инструмента `X.Y.Z`
- **THEN** образ доступен по тегам `X.Y.Z` и `latest`, а метаданные образа сообщают версию `X.Y.Z`

#### Scenario: Версия внутри образа

- **WHEN** в контейнере выполнена команда `c4builder --version`
- **THEN** выводится та же версия `X.Y.Z`, что и в теге образа
