## Context

`C4ComponentAttribute` публикуется NuGet-пакетом и входит в публичный контракт (мотивация —
`proposal.md`, раздел Why). Сейчас описание задаётся свойством `Description { get; set; }`, а
анализатор читает применение атрибута через Roslyn `AttributeData` в
`C4ModelBuilder.Analyzer/Infrastructure/AttributeDataExtensions.cs`.

## Goals / Non-Goals

**Goals:**

- Сделать описание обязательным так, чтобы обязательность гарантировал компилятор.
- Сохранить наблюдаемое поведение диаграммы: компонентом остаётся узел с заданным описанием.

**Non-Goals:**

- Правила состава дерева вызовов, типизация компонентов и разрешение ссылок не меняются.
- Совместимость со старой формой разметки не обеспечивается.

## Decisions

**1. Описание и `isRoot` — параметры конструктора, свойства только для чтения.**
`C4ComponentAttribute(string description, bool isRoot = false)`.

Альтернативы: оставить свойство с `[Obsolete]` — отвергнуто, потому что описание перестаёт быть
обязательным, а старый синтаксис продолжает компилироваться; перенести в конструктор только
описание, оставив `IsRoot` свойством — отвергнуто, потому что в одном атрибуте появились бы две
разные формы инициализации. Выбранная форма совпадает со стилем пакета:
`C4ContainerAttribute(string name, string description)`.

**2. Анализатор читает аргументы конструктора, а не свойства.**
`GetC4ComponentDescription` берёт `ConstructorArguments[0]`, `IsRootC4Component` —
`ConstructorArguments[1]` при его наличии.

Почему свойства не заменяют аргументы: анализатор никогда не получает экземпляр атрибута, он
работает с `AttributeData` — описанием применения из метаданных. Позиционные аргументы попадают
в `ConstructorArguments`, именованные — в `NamedArguments`, а сами свойства доступны только
потребителям через рефлексию (`GetCustomAttribute<C4ComponentAttribute>()`) и анализатору не
видны. После перехода обработка `NamedArguments` удаляется: свойство только для чтения нельзя
использовать как именованный аргумент, поэтому этот путь становится недостижимым.

**3. `null` запрещается настолько, насколько это возможно.**
Параметр объявляется non-nullable `string`, а в репозитории `dotnet_diagnostic.cs8625.severity`
поднимается с `warning` до `error`. Полный запрет у потребителей недостижим: аргумент атрибута —
константа, а nullability — предупреждение, которое становится ошибкой только в настройках их
проекта. Если `null` всё же приходит, описание считается незаданным и узел не становится
компонентом — без исключений и без записей в лог.

В `C4ModelBuilder.Attributes` nullable-контекст отключён (конвенция проекта), поэтому аннотация
включается файловой директивой `#nullable enable` в `C4ComponentAttribute.cs`: без неё параметр
попал бы в метаданные как oblivious, и `cs8625` у потребителей не сработал бы.

**4. Границы слоёв.**
Правки идут по цепочке `C4ModelBuilder.Attributes` (публичный контракт) →
`C4ModelBuilder.Analyzer/Infrastructure` (чтение атрибута) → `C4ModelBuilder.Sample.Target` и
`C4ModelBuilder.Analyzer.Tests` (разметка). `C4ModelBuilder.Models`,
`C4ModelBuilder.PlantUmlCreator` и `C4ModelBuilder.Cli` не затрагиваются; ссылки между слоями
не меняются.

## Risks / Trade-offs

- [Атрибут переписан, а читатель — нет] → `GetC4ComponentDescription` переходит на
  `ConstructorArguments`; проверка — `scripts/Invoke-Sample.ps1` даёт непустой `.puml`: тесты
  анализатора этот рассинхрон не поймают, так как разметка в них задаётся строками.
- [Потребители ломаются на обновлении пакета] → миграция в две строки описана в `proposal.md` и
  README, версия поднимается до 3.0.0, чтобы обновление не пришло неожиданно.
- [`null` остаётся возможным у потребителя] → принято: в нашем репозитории `cs8625` — ошибка,
  у потребителя — предупреждение; поведение при `null` определено спекой.
- [Поднятие `cs8625` до ошибки может сломать сборку] → проверено: в текущей сборке предупреждений
  `cs8625` нет (только `CA1502`, `CA1506`, `CA1812`).

## Migration Plan

1. Заменить разметку: `[C4Component(Description = "X")]` → `[C4Component("X")]`,
   `[C4Component(IsRoot = true, Description = "X")]` → `[C4Component("X", isRoot: true)]`.
2. Обновить версию пакета до 3.0.0 в проекте потребителя.
3. Откат: вернуться на 2.0.1 — прежняя форма разметки перестанет компилироваться, поэтому откат
   возможен только вместе с откатом разметки.
