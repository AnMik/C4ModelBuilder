# Spec Delta

## MODIFIED Requirements

### Requirement: Структура генерируемого текста

Результат SHALL начинаться строкой `@startuml` и завершаться строкой `@enduml`. Диаграмма SHALL
подключать библиотеку C4 Component локальным включением `!include <C4/C4_Component.puml>` без
обращения к внешнему URL. Для каждого компонента SHALL выводиться макрос `Component(alias, name,
technology, description)`, где `technology` — третий позиционный аргумент, а `description` —
четвёртый; для каждой связи — макрос `Rel(from, to, description)`. Порядок строк и пробелы
SHALL NOT считаться частью контракта.

#### Scenario: Пустая диаграмма

- **WHEN** в дереве вызовов нет ни одного компонента
- **THEN** результат содержит только заголовок, завершение и подключение библиотеки

#### Scenario: Компоненты и связи

- **WHEN** модель диаграммы содержит компоненты и связи между ними
- **THEN** для каждого компонента в тексте есть макрос `Component(...)`, для каждой связи —
  макрос `Rel(...)`

#### Scenario: Локальное подключение библиотеки

- **WHEN** формируется текст диаграммы
- **THEN** подключение библиотеки выполняется включением стандартной библиотеки, а не загрузкой
  по внешней ссылке

#### Scenario: Описание в слоте описания

- **WHEN** компонент имеет описание
- **THEN** описание выводится четвёртым позиционным аргументом макроса `Component`, а не третьим

#### Scenario: Технология в слоте технологии

- **WHEN** компонент имеет технологию
- **THEN** технология выводится третьим позиционным аргументом макроса `Component`

#### Scenario: Компонент без технологии

- **WHEN** компонент не имеет технологии
- **THEN** третьим аргументом макроса `Component` выводится пустая строка, а описание остаётся
  четвёртым аргументом

#### Scenario: Технология и цветовой тег вместе

- **WHEN** компонент имеет технологию, из которой выводится цветовой тег
- **THEN** в макросе `Component` выводятся и технология, и этот тег

### Requirement: Типизация компонентов

Компонент SHALL получать цветовой тег `repository`, если его технология содержит подстроку
`Repository`, и тег `gateway`, если технология содержит подстроку `Gateway`; сравнение SHALL
выполняться без учёта регистра, а проверка `Repository` SHALL выполняться раньше проверки `Gateway`.
Имя компонента SHALL NOT влиять на выбор тега. Компонент без технологии или с технологией, не
содержащей ни одной из подстрок, тег не получает. Тег SHALL отображаться в тексте как тег элемента.

#### Scenario: Компонент-репозиторий

- **WHEN** технология компонента содержит `Repository`
- **THEN** компонент выводится с тегом `repository`

#### Scenario: Компонент-шлюз

- **WHEN** технология компонента содержит `Gateway`, но не содержит `Repository`
- **THEN** компонент выводится с тегом `gateway`

#### Scenario: Обычный компонент

- **WHEN** технология компонента не содержит ни `Repository`, ни `Gateway`
- **THEN** компонент выводится без тега типа

#### Scenario: Технология не задана

- **WHEN** у компонента нет технологии
- **THEN** компонент выводится без тега типа

#### Scenario: Имя компонента не влияет на тег

- **WHEN** компонент назван `OrderRepository`, но технологии у него нет
- **THEN** компонент выводится без тега типа
