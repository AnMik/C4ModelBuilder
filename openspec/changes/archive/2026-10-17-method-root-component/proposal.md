# Proposal

## Why

Разметка `[C4Component("...", isRoot: true)]` на методе компилируется (атрибут применим к методу), но
анализатор собирает корневые компоненты только из классов: `SolutionAnalyzer.AnalyzeComponents` читает
`isRoot` у классов. Разработчик, пометивший метод, получает ровно тот же результат, что и без разметки,
без диагностики и без намёка на причину. Молчаливое игнорирование выглядит как дефект контракта: атрибут
разрешает такую разметку, спека описывает метод как узел-компонент, но отдельная диаграмма не появляется.

## What Changes

- `AnalyzeComponents` дополнительно собирает корни среди методов: метод класса из анализируемых проектов
  с `C4Component.IsRoot == true` порождает собственное дерево вызовов.
- Корневой узел такого дерева — сам метод с именем `Class.Method`; описание берётся из атрибута метода,
  дочерние узлы — вызовы из тела метода. Отдельный узел-класс в дерево не добавляется (в том числе для
  вызовов других методов этого класса), поэтому метод остаётся единственным корнем диаграммы.
- Классовые корни работают как раньше. Если корнем помечены и класс, и его метод, генерируются оба
  дерева и оба файла: одно не заменяет и не схлопывает другое.
- Видимость метода не ограничивает: приватный метод с `isRoot = true` тоже становится корнем.
- Глубина анализа для метода-корня отсчитывается так же, как для методов корневого класса: корневой
  метод анализируется с глубиной `0`, лимит `--max-depth` не меняет смысла.
- CLI записывает файл метода как `{Class}.{Method}.{расширение}`; правило `{Class}.{расширение}` для
  классов не меняется.
- **Влияние на публичный контракт**: изменение аддитивное. Сигнатуры атрибутов, публичный API библиотеки
  и параметры CLI не меняются; `C4ComponentAttribute` уже объявлен с `AttributeTargets.Method`. Версия
  пакета `C4ModelBuilder.Attributes` не поднимается, версия `C4ModelBuilder.Cli` поднимается — меняется
  набор выходных файлов.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `c4-annotation-attributes`: семантика `isRoot` на методе — метод становится точкой входа анализа и
  источником отдельной диаграммы (добавляется требование; существующее требование о классе не меняется).
- `cli-tool`: требование «Формирование выходных файлов» обобщается с «корневого класса» на «корневой
  компонент»; задаётся имя файла для метода и поведение при одновременных корнях класса и метода.

## Не входит в объём

- Формат текста диаграммы: спека `component-diagram-generation` не меняется — слияние дерева и рендер
  от вида корня не зависят.
- Слияние и дедупликация диаграмм класса и его методов, единая диаграмма на класс.
- Предупреждения и диагностика разметки, в том числе для `isRoot` на неподдерживаемых целях.
- Корни на методах интерфейсов, локальных функциях и top-level statements: сканируются только
  объявления методов внутри классов.
- Ограничение корней по видимости или модификаторам (`static`, `async`) и новые параметры CLI для
  отбора корней.
- Изменение семантики `--max-depth` и правил обхода вызовов.
- Изменения в `C4ModelBuilder.Models` и `C4ModelBuilder.PlantUmlCreator`.

## Impact

- Код: `C4ModelBuilder.Analyzer/SolutionAnalyzer.cs` (сбор корней и общий построитель дерева),
  `C4ModelBuilder.Analyzer/MethodAnalyzer.cs` (вызовы методов класса-владельца корня-метода идут без узла-класса),
  `C4ModelBuilder.Analyzer.Tests/SolutionAnalyzerTests.cs` (регрессионные тесты),
  `C4ModelBuilder.Cli/C4ModelBuilder.Cli.csproj` (версия), `C4ModelBuilder.Sample.Target` (пример разметки).
- Документация: `README.md` (раздел «Как элементы попадают на диаграмму»), `AGENTS.md` (ключевые файлы,
  известные точки внимания).
- Не затрагиваются: `C4ModelBuilder.Attributes`, `C4ModelBuilder.Models`, `C4ModelBuilder.PlantUmlCreator`.
- Риски: рост числа файлов на запуск; коллизия имён при совпадении `Class.Method` в разных пространствах
  имён — последний файл затирает предыдущий (то же правило, что для одноимённых классов); дублирование
  содержимого, если корнем помечены и класс, и его метод.
