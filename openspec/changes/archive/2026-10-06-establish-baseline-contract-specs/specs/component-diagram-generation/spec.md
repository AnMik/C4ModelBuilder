## Purpose

Задаёт контракт содержимого генерируемого текста PlantUML: структуру файла, состав компонентов
и связей, а также правила типизации компонентов. Порядок строк и пробелы не фиксируются.

## ADDED Requirements

### Requirement: Структура генерируемого текста

Результат SHALL начинаться строкой `@startuml` и завершаться строкой `@enduml`. Диаграмма SHALL
подключать библиотеку C4 Component локальным включением `!include <C4/C4_Component.puml>` без
обращения к внешнему URL. Для каждого компонента SHALL выводиться макрос `Component(alias, name,
description)`, для каждой связи — макрос `Rel(from, to, description)`. Порядок строк и пробелы
SHALL NOT считаться частью контракта.

#### Scenario: Пустая диаграмма

- **WHEN** в дереве вызовов нет ни одного компонента
- **THEN** результат содержит только заголовок, завершение и подключение библиотеки

#### Scenario: Компоненты и связи

- **WHEN** модель диаграммы содержит компоненты и связи между ними
- **THEN** для каждого компонента в тексте есть макрос `Component(...)`, для каждой связи —
  макрос `Rel(...)`

#### Scenario: Локальное подключение библиотеки

- **WHEN** формируется текст диаграммы
- **THEN** подключение библиотеки выполняется включением стандартной библиотеки, а не загрузкой
  по внешней ссылке

### Requirement: Определение компонентов

Компонентом SHALL становиться узел дерева вызовов, для которого задано описание (значение
`Description` атрибута `C4Component`, отличное от отсутствия значения). Узел без описания
компонентом не становится и SHALL NOT попадать в список компонентов диаграммы.

#### Scenario: Узел без описания

- **WHEN** узел дерева не имеет описания
- **THEN** компонент для него не создаётся

#### Scenario: Узел с пустым описанием

- **WHEN** для узла задано описание, равное пустой строке
- **THEN** компонент создаётся, а его описание выводится пустым

#### Scenario: Связь через узел без описания

- **WHEN** узел без описания вызывает узел-компонент
- **THEN** связь протягивается от ближайшего компонента-предка к вызванному компоненту

### Requirement: Связи между компонентами

Связи SHALL устанавливаться между ближайшим компонентом-предком и вызванным компонентом.
Повторяющиеся связи SHALL выводиться один раз, связь компонента с самим собой SHALL NOT
создаваться.

#### Scenario: Вызов компонентом самого себя

- **WHEN** компонент вызывает сам себя
- **THEN** связь компонента с самим собой не создаётся

#### Scenario: Вызов нескольких компонентов

- **WHEN** один узел вызывает несколько разных компонентов
- **THEN** создаётся отдельная связь для каждого вызванного компонента

#### Scenario: Повторяющаяся связь

- **WHEN** одна и та же пара компонентов встречается в дереве несколько раз
- **THEN** в тексте диаграммы связь выводится один раз

### Requirement: Типизация компонентов

Компонент SHALL получать тип `repository`, если его имя содержит подстроку `Repository`, и тип
`gateway`, если имя содержит подстроку `Gateway`; сравнение SHALL выполняться без учёта
регистра. Проверка `Repository` SHALL выполняться раньше проверки `Gateway`. Для остальных
компонентов тип считается обычным. Тип SHALL отображаться в тексте как тег элемента.

#### Scenario: Компонент-репозиторий

- **WHEN** имя компонента содержит `Repository`
- **THEN** компонент выводится с тегом `repository`

#### Scenario: Компонент-шлюз

- **WHEN** имя компонента содержит `Gateway`, но не содержит `Repository`
- **THEN** компонент выводится с тегом `gateway`

#### Scenario: Обычный компонент

- **WHEN** имя компонента не содержит ни `Repository`, ни `Gateway`
- **THEN** компонент выводится без тега типа

### Requirement: Индикация некорректного входа

Формирование диаграммы SHALL отклонять отсутствующее дерево вызовов, сообщая об ошибке аргумента.

#### Scenario: Дерево не задано

- **WHEN** на вход передано отсутствующее дерево вызовов
- **THEN** возникает исключение об ошибке аргумента `ArgumentNullException`
